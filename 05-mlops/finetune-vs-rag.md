# Fine-tune vs RAG 取捨

## 人話（為什麼要懂）

面試成日問：「知識應唔應該 fine-tune 入模型？」後端角度好似問：**配置／文檔放 DB 定寫死喺代碼？**  
**RAG**＝查庫再答：知識可更新、可引用、可按租戶過濾；代價係檢索鏈路、延遲、chunk／權限要維護。  
**Fine-tune（含 LoRA）**＝改模型行為同「口吻／格式」：適合穩定嘅風格、術語、工具 schema、拒答策略；唔適合把會變嘅費率、公告、機密寫入權重。

生產幾乎一定 **hybrid**：行為同格式靠輕量 FT／好 prompt，事實靠 RAG；兩者各解一類問題，唔好互相硬撐。

## 面試短答

- **偏 RAG**：知識常變（政策、費率、產品文檔）；要 **可引用／可審計**；**多租戶**文檔隔離；避免把秘密／PII **烤進權重**；單一基座服務多業務知識。
- **偏 Fine-tune**：風格／語氣／品牌口吻；固定輸出格式、tool calling schema；領域黑話同寫法；想縮短 prompt（少 few-shot）降延遲／成本；檢索解決唔到嘅 **行為**（拒答、安全邊界、結構化可靠度）。
- **Hybrid 常見**：LoRA 教「點講、點呼叫工具」；RAG 教「呢刻事實係咩」。Eval 要分開：行為回歸 vs 知識／ grounding。
- **成本／運維**：
  - FT：數據管線、標註質量、訓練／評估回歸、版本同回滾、serving（多 adapter）複雜度。
  - RAG：索引新鮮度、chunking、權限過濾、embedding 變更要 rebuild、檢索 eval。
- **Anti-patterns**：用 FT「背」成日變嘅 FAQ／匯率；用 RAG 硬拗純風格／格式控制；把 API key、用戶私信、內部風控規則 FT 入模。
- **CEX／後端視角**：產品 FAQ＋合規政策 → **RAG**（權限＋引用）；ticker 黑話／客服語氣／提幣工具 JSON schema → **輕量 LoRA／FT**；**永不**把 PII、密鑰、未公開風控閾值 FT 入模。

## 常見追問（連答案）

**Q：點解唔好 fine-tune 去「記住」成日改嘅費率？**  
A：權重更新慢、貴、難審計；改一次要重訓／發版；用戶問「依家手續費」需要實時真相同引用來源。費率放配置／DB＋RAG 或直接工具查 API，模型只負責解釋同格式化。FT 背費率＝把會變嘅 config compile 進 binary。

**Q：RAG 已經好強，仲要唔要 FT？**  
A：要睇失敗模式。若檢索對但仍：語氣唔穩、JSON／tool 亂、亂承諾、拒答邊界飄——呢啲係行為問題，RAG 加 context 未必穩，輕量 FT／LoRA 或嚴格 decoding（constrained decoding）更對症。若係找錯文檔、過期知識——先修檢索同新鮮度，唔好先 FT。

**Q：LoRA 同全量 FT 點揀？**  
A：多數業務適配用 LoRA：成本低、可多 adapter、易回滾。全量 FT 要更大數據同風險（災難性遺忘），通常留俾基礎模型廠或極大領域遷移。Serving 要計多 LoRA 嘅顯存／切換開銷（可提 multi-LoRA serving）。

**Q：數據同合規上 FT vs RAG 有咩分別？**  
A：FT 訓練集一旦含 PII／秘密，可能進權重同之後輸出，難保證「刪得清」；RAG 文檔可刪可 ACL，引用可審計。合規友好做法：訓練集脫敏、最小必要；事實與用戶數據走 RAG／工具，唔進訓練。

**Q：點樣用 eval 決定選邊條路？**  
A：建兩類集：①知識題（要引用、會過期）——應測 RAG hit＠k、忠实度；②行為／格式題（tool schema、拒答、語氣）——應測 schema 通過率、Rubric／人工。若①差 → 投 RAG；若②差而①已可 → 投 FT／約束解碼。改完兩邊都跑回歸，防修好行為弄壞 grounding。

## 小練習

**題：** 交易所要做「智能客服」：要答最新充提政策、要穩定輸出工單 JSON 俾後端、語氣要統一、仲有內部未公開嘅風控規則。邊啲用 RAG、邊啲用 FT、邊啲兩者都唔好進模型？點分層？

**參考答案：**  
- **RAG**：公開／對客嘅充提政策、幫助中心、公告（帶租戶／語言／權限過濾、引用、索引新鮮度）。  
- **FT／LoRA**：統一客服語氣、工單 JSON／tool schema 穩定性、常見黑話理解（「打幣」「上分」）；用脫敏對話同合成 schema 樣本。  
- **唔好進模型（唔 FT、亦唔裸放進一般 RAG）**：未公開風控閾值、內部黑名單邏輯、用戶 PII——改走後端工具／權限 API，模型只得「已授權嘅結論」或拒答。  
- **Hybrid**：請求 →（可選）意圖分類 → RAG 取政策 → LoRA 模型按 schema 產出；eval 分知識忠实度同 schema／拒答回歸；secret 永不進權重。
