# Fine-tune 數據管線（來源、洩漏、產明日誌同版本）

> 2026-11-10 · AI warm-up · 工程面試向  
> 幾時該 FT、幾時該 RAG 見 [`finetune-vs-rag.md`](./finetune-vs-rag.md)；LoRA 點 serve 見 [`lora-multi-adapter-serving.md`](./lora-multi-adapter-serving.md)；**本篇只講：訓練數據從邊來、點閘質量、點避免自己騙自己。**

## 人話

Fine-tune 好不好，好多時 90% 睇數據，唔係學習率。後端直覺好似風控／反欺詐模型嘅特徵同標籤管線：來源雜、標籤會漂、一唔小心就把「已經上線嗰套」嘅偏差再烤入去。面試官想聽：**數據從邊來、點過濾同脫敏、train/val/test 點切先唔洩漏、產明日誌點用先唔放大現況錯誤、以及 dataset 點版本化同回滾。**

## 面試短答

- **來源分層，唔好一鍋炒。** （1）專家示範／標註；（2）合成（教師模型 + 人工抽檢）；（3）產明日誌（要經過品質閘，唔能裸用）。每條樣本記來源、授權、時間、標註指引版本。
- **品質閘係管線，唔係事後抽樣。** 去重（含近重複）、長度／語言、格式／schema 可解析、毒性／越權示範剔除、PII／密鑰／內部風控閾值脫敏或丟棄、明顯錯誤示範隔離。過唔到閘嘅唔入訓練。
- **切分單位要高過「一句 turn」。** 按 `user`／`ticket`／`doc`／對話切 train/val/test，唔好按訊息隨機切——同一單兩邊都有就係洩漏，線上指標會虛高。
- **Eval 污染。** Held-out 同公開 benchmark 題目唔可以混入訓練或合成教師嘅 prompt。定期加新題，防模型「背熟呢份考卷」。RAG 文檔若被拿去 FT，亦要檢查同知識類 eval 重疊。
- **SFT vs preference（DPO／RLHF 類）。** SFT 教「呢個輸出係示範」；preference 教「A 比 B 好」。成對標註要有穩定 rubric（正確性、拒答、語氣、工具是否該呼叫），唔好只問「邊條順眼」。兩種數據要分開版本，唔好把偏好對當成無條件正確答案做 SFT。
- **產明日誌最大坑係選擇偏差。** 只拿「用戶冇撳差評」嘅回覆當正例＝把現況模型嘅錯同偏都當成真理（feedback loop）。工具失敗、越權、事後被人工改正嘅單，應該進 **correction** 集，唔好當成功示範。抽樣要覆蓋失敗模式，而唔係只抽高流量 FAQ。
- **合成數據。** 可以補稀有意圖同 schema 樣本，但要多樣性約束、教師同被訓模型盡量唔同源、人工抽檢比例寫死。合成佔比過高會模式崩潰（答案好似、錯法好似）。唔能 100% 替代金標。
- **版本同 lineage。** `dataset_version` + data card（來源、授權、PII 處理、切分種子、過濾規則）；訓練配置釘死（base model、LoRA rank、超參）。可復現、可回滾；線上 adapter 要對到用咗邊一版數據。
- **迭代靠誤差分析，唔靠盲目加數據。** 先睇 held-out 邊類掛（拒答邊界、工具 schema、某個產品線），再定向補樣本同回歸，避免修好 A 弄壞 B。
- **合規。** 用戶對話要有授權同脫敏先入集；「被遺忘權」對已烤進權重嘅樣本好難徹底刪，所以 **入集前就要脫敏／最小必要**。Secret、未公開風控規則永不進訓練（同 FT vs RAG 篇一致）。
- **CEX 類比：** 似反欺詐訓練——用「已上線規則放行嘅單」當負例會 tautology；標籤要獨立、切分要按帳戶、特徵同標籤要有時間先後（唔用未來資訊）。

## 常見追問（連答案）

**Q1：直接把最近三個月客服對話連同當時模型回覆丟去 SFT，有咩問題？**  
A：至少五個：（1）PII／帳戶資料／可能有密鑰進權重，刪唔清；（2）選擇偏差同 feedback loop，現況錯法被加固；（3）按 turn 隨機切會洩漏；（4）失敗／人工改正單被當成示範；（5）無 dataset 版本，出問題無法回滾同追究。正確係脫敏 → 品質閘 → 按 ticket 切分 → 失敗單進 correction 或 preference 對 → 先小集 LoRA 睇 held-out 再擴。

**Q2：點證明 held-out 冇被污染？**  
A：切分按更高單位並把種子寫進 data card；訓練前對 train 同 test 做精確／近重複檢出（n-gram、embedding 近鄰）；禁止用 test 題去 prompt 教師模型合成；eval 集權限分開，訓練 job 讀唔到。若發現重疊，要重切並作廢受污染嘅分數，唔好只刪重疊行繼續吹成績。

**Q3：合成數據可以佔幾多？**  
A：冇萬能比例，但要講原則：金標／專家示範負責行為邊界同高風險意圖；合成負責補稀疏類同格式。設上限（例如先 30–50%）並做消融：加合成後 held-out 真標是否仍升。每批合成固定抽檢，教師模型同評測 judge 盡量分開。高風險（資金建議、合規拒答）以人工金標為準。

**Q4：用戶要求刪除對話，但已經 fine-tune 過，點辦？**  
A：權重入面嘅影響幾乎無法精確「刪一條」。實務：入集前脫敏同最小化；記錄每條樣本 id 進咗邊個 `dataset_version`；刪除請求之後 **唔再入未來數據集**；高風險或大量刪除時考慮用唔含該批數據嘅版本重訓／回滾 adapter。面試要主動講「FT 對遺忘權不友好，所以產數階段先擋，而唔係事後從權重挖走」。

**Q5：多個租戶嘅對話可唔可以混嚟訓一個共享 LoRA？**  
A：要睇授權同隔離。租戶專有話術、內部政策、客戶名單唔能進共享權重；共享 adapter 只用普遍、已授權、脫敏嘅行為／schema 樣本。租戶專屬知識走 RAG＋ACL，或單獨 adapter。混訓前要做成員資格同資料分級，避免一個租戶嘅內容被另一個套出嚟（好似多租戶緩存沒隔離）。

## 小練習

**題：** 產品想為交易所智能客服做 LoRA，提案係：「把最近 3 個月約 50 萬條對話，連同當時 bot 回覆，全部丟去訓；隨機 95/5 切訓練同測試；合成再翻一倍；下週上線。」請指出至少五個問題，並寫一條你會落地嘅數據管線（含合規同評估）。

**參考答案：**  
1. **問題：** 未脫敏（PII／可能有帳戶同憑證）；裸用產週回覆＝feedback loop；95/5 按條數隨機切，同一 ticket 洩漏；無品質閘、失敗單當正例；合成翻倍無抽檢同消融；無 dataset version／授權；高風險資金／風控內容可能入模；無獨立 held-out 同行為 vs 知識分測。  
2. **管線：** 授權範圍內導出 → PII／密鑰／內部規則掃描同脫敏（過唔到就丟）→ 去重／毒性／schema 閘 → 按 `ticket_id` 切 train/val/test（種子寫死）→ 成功示範入 SFT；人工改正同偏好對入 correction／DPO 集；失敗同越權唔當正例。  
3. **合成：** 只補稀疏意圖同工單 JSON，教師模型獨立，固定抽檢，做「有／無合成」消融；資金／合規類以專家金標為準。  
4. **評估：** 知識題唔靠 FT 背（走 RAG eval）；行為題測 schema、拒答、語氣；確認 test 同 train 近重複為零；線上先 shadow／小 canary。  
5. **版本：** `dataset_v1` data card + 對應 adapter `lora_v1`；可回滾；刪除請求唔進後續版本。下週全量上線唔成立，先小集驗證再擴。
