# HyDE／Query 改寫深挖：假答案只係檢索鉤，唔係真相

> 2026-11-28 · AI warm-up · 工程面試向  
> 改寫總覽見 [query-rewriting.md](./query-rewriting.md)；迭代檢索見 [agentic-iterative-retrieval.md](./agentic-iterative-retrieval.md)；路由見 [query-corpus-routing.md](./query-corpus-routing.md)；線上評估見 [../07-system-design/online-retrieval-eval.md](../07-system-design/online-retrieval-eval.md)。**本篇講：點解問句同文檔喺向量空間唔對稱、HyDE 只用於檢索、何時唔好開、同原句／BM25 點並行、改寫甩實體同延遲預算。**

## 人話

用戶問句通常又短又似口語：「VIP 提 ETH 幾多錢？」「咁佢呢？」文檔卻係陳述句同表格。Dense retriever 若未把「短問題」同「長陳述」對齊得好，兩種向量會唔喺同一個社區，直接 embed 原句可能搵唔準。

**HyDE**（Hypothetical Document Embeddings）嘅做法係：先叫 LLM 寫一段「假如知識庫入面有答案，嗰段可能點寫」嘅**假想文檔**，再對呢段假文做 embedding，去向量庫搵**真**文檔。關鍵一句：**假文只係檢索用嘅鉤，絕對唔可以當答案，亦唔可以當引用來源。**

後端類比：你唔會用「AI 估出嚟嘅訂單」直接入帳，只會用佢當搜尋條件去撈真訂單；撈唔到就話搵唔到，唔好把估嘅內容顯示俾客戶。面試官想聽：不對稱問題、唔取代原 query／BM25、幻覺實體會帶錯庫、改寫喺 TTFT 關鍵路徑、同 multi-query／condense 嘅分工。

## 面試短答

- **要解決嘅係「問句同文檔形態唔對稱」，唔係「令模型識答」。** HyDE 改變嘅係檢索向量；生成仍然只准用檢索返嚟嘅真文檔。把假答案直接回給用戶，就係未檢索就幻覺。
- **原 query 同 BM25 要留底。** 標準組合：原句 dense ＋ HyDE dense ＋ 原句 BM25（必要時再加 condense／multi-query），RRF 或打分融合後 rerank。改寫一旦改錯實體，純 HyDE 會成盤皆輸。
- **精確標識、交易對、錯誤碼、訂單號通常唔開 HyDE。** 「USDT-TRC20」「0x 交易哈希」「錯誤碼 30007」要原樣保留；假文一旦寫成「USDT」或亂編費率，會撈錯鏈或錯表。用路由：短開放題、語義落差大先考慮 HyDE；關鍵詞／ID 型走原句＋BM25。
- **假文入面嘅「事實」不可信。** 模型可能編一個似是而非嘅 VIP ETH 提現費；向量會被帶去討論該費率嘅段落，或者更糟，帶去完全唔同產品。要做實體校驗：原 query 抽出嘅交易對、網絡、產品名，改寫後必須仍在；唔在就丟棄改寫、回退原句。
- **延遲在檢索之前，食 TTFT。** HyDE 要先等一次 LLM 先至可以搜。用細模型、硬 timeout、同「原句檢索」並行（HyDE 未返就先用原句出候選，返到再融合）、高頻問句 cache 假文／向量。設唔到預算就寧願不開。
- **唔等於 multi-query，亦唔等於第二跳。** Multi-query 係把問題拆成幾條短查詢；HyDE 係生成文檔形態嘅段落；multi-hop／iterative 係用第一跳結果再搜。可以疊加，但三重都開要計清楚跳數同成本。
- **新式 embedding 唔保證 HyDE 多餘。** 指令前綴、query／doc 分開 encode 嘅模型收窄咗不對稱，但係咪仲有收益要用自己嘅 slice 量，唔好背論文數字。版本要釘：`rewrite_prompt_version`、生成模型、embedding 模型；prompt 一改視作新實驗。
- **ACL 同租戶唔交俾改寫模型。** 改寫只改文本；過濾喺檢索層硬加。評估要分 slice：多輪指代、開放 how-to、精確 ID／費率；只報平均 recall 會掩蓋「開放題升、費率題跌」。

## 常見追問（連答案）

**Q1：HyDE 生成嘅段落可唔可以引用、或者當答案？**  
A：唔可以。佢冇經過知識庫，可能全錯。引用同答案只准來自檢索到嘅真文檔（同受控表）。假文只進 embedding，唔進用戶可見上下文，以免模型「順手抄自己編嘅費率」。

**Q2：同 query expansion、multi-query、condense 點揀？**  
A：多輪「咁佢呢？」先 condense 補實體，呢步收益通常最大。一條問題含多個獨立子問題先 multi-query。短、開放、文檔好長而問句好短，先試 HyDE。精確查找優先原句＋BM25。唔好默認四種全開。

**Q3：假文寫錯費率，會發生咩事？**  
A：向量會偏向「討論嗰個錯數」嘅段落，或者相似產品。所以：硬保留實體；BM25 用原 query；HyDE 只加成票、唔否決原句命中；費率類題路由關閉 HyDE，數字以受控表為準。

**Q4：點解唔用同一個 LLM 直接答，仲檢索？**  
A：因為你要可追溯、可權限過濾、可更新。HyDE 只係改善召回嘅技巧；生成仍然要 grounded 喺檢索結果。模型識答唔等於呢個租戶而家嘅費率。

**Q5：延遲同成本點控？點知有冇幫到？**  
A：細模型、timeout、同原句檢索並行、熱問 cache。用 retrieval eval 分 slice 對比「只原句」vs「原句＋HyDE」嘅 Hit@k／MRR，同時睇 P95 TTFT。開放題升、標識題跌就要加路由而唔係全站常開。改寫 prompt 要入版本，同埋監控「改寫丟實體」率。

## 小練習

**題：** 客服 RAG。同事方案：所有問題先用大模型寫一段「標準答案」做 HyDE，只用呢段嘅向量去搜，BM25 同原句都關；生成時把假答案同檢索段落一齊塞進 prompt，話可以「互相印證」；「USDT-TRC20 充值未到」被改寫成「USDT 到帳時間」；改寫無 timeout，失敗就整單失敗；無 slice 評估，只睇平均 cosine 升咗就全量開。你會點評，同埋會點落地？

**參考答案：**

1. **假答案唔可以當生成上下文，更加唔係引用源**；只用於檢索向量。
2. **必須保留原句 dense＋BM25**，同 HyDE 融合，避免改寫改錯就零召回。
3. **「USDT-TRC20」屬精確標識**，路由關閉 HyDE 或硬保留實體，否則撈錯鏈。
4. **改寫用細模型、硬 timeout，並同原句檢索並行**；改寫失敗就回退原句，唔好整單失敗。
5. **分 slice 睇 Hit@k／答案正確率同 P95 TTFT**，唔好用平均 cosine。費率／鏈／錯誤碼以受控數據為準。
