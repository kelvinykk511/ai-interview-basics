# 幻覺、Grounding 與 Citations

## 人話

LLM 很會「把話說圓」，不一定對。Grounding = 強迫回答貼著你給的證據（檢索到的文件、工具回傳、DB 結果），講不出依據就說不知道。Citation = 答案裡標出「這句來自哪一段」——像後端 API 回傳要帶 `sourceId`，方便人核對、也方便你做拒答與追責。

## 面試短答

- **幻覺類型**：捏造事實／引用不存在的來源／把檢索片段過度推論（超出證據）。面試要分「模型胡謅」vs「檢索錯／上下文錯導致的錯答」。
- **Grounding 策略**：system 明確「只根據提供的 context；沒有就說沒有」；把證據放進 prompt；要求引用 chunk id；對高風險欄位（金額、合約地址、狀態）走**結構化抽取＋校驗**，不要只靠散文生成。
- **Citation 落地**：每個檢索 chunk 帶穩定 id；生成時輸出 `[doc:3]` 或 JSON `{answer, citations[]}`；後端再核對 citation 是否真在本次 context 裡（防「假引用」）。
- **拒答／降級**：置信度低、檢索分數低、引用對不上 → 回「資料不足／請人工」或只回可核對欄位。CEX 直覺：資金相關寧可拒答，不要瞎編 SOP。
- **和 RAG／Eval 的關係**： grounding 失敗常是 retrieval miss 或 chunk 切太碎；評估要分開看「有沒有檢到對的」vs「檢到了有沒有照著講」。

## 常見追問（含答案）

**Q：加了「請根據資料回答」就夠了嗎？**  
A：不夠。Prompt 約束會漏；模型仍可能忽略 context 或編造 citation。要配：強制輸出格式、後端校驗引用、低分拒答、以及用 golden set 測「無依據時是否拒答」。

**Q：Citation 和「可解釋性」一樣嗎？**  
A：不一樣。Citation 是**可核對的來源指針**；模型內心推理仍可能是黑盒。面試講：工程上優先可審計引用，而不是假裝有完整可解釋性。

**Q：檢索分數高就等於答案可信？**  
A：否。高相似可能是錯文件、過期 SOP、或問句與標題碰巧像。還要：權限／時間 metadata、rerank、業務規則校驗（例如狀態機允許的下一狀態）。

**Q：長答案怎麼做 grounding？**  
A：分段主張（claim）各自綁 citation；或先抽結構化字段再組裝文案。關鍵數字／ID 用工具／DB 查，不讓模型「算」或「記」。

## 小練習

**題：** 客服 bot 常回「依規定 24 小時內到帳」，但知識庫裡其實寫的是「網絡確認後 1–3 個區塊」。你要在系統層（不是只改 prompt）加哪三道防線？  

**參考答案：**  
1. **強制 citation＋後端校驗**：答案必須引用當次 context 的 chunk id；引用缺失或 id 不在 context → 攔截／改寫為拒答。  
2. **高風險槽位結構化**：到帳時間、網絡、幣種從檢索結果用抽取／規則填槽，生成層只潤色已校驗字段。  
3. **Eval／線上監控**：golden 題含「過期說法 vs 現行 SOP」；線上抽樣查「無引用率、引用不匹配率、人工差評含幻覺標籤」，並對低檢索分路由人工。
