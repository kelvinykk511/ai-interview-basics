# RAG 架構（檢索增強生成）

## 人話

模型不一定「記得」你司內部資料。RAG = 先**搜相關文件片段**，再把片段塞進 prompt 讓模型依據這些內容回答——像開卷考試。

## 面試怎麼答（端到端）

1. 文檔切塊（chunk）→ embedding → 寫入向量庫
2. 用戶問題 → embedding → top-k 相似檢索（可加關鍵詞／權限過濾）
3. 組裝 prompt（系統指令 + 檢索片段 + 問題）→ LLM → 回答（最好帶引用）

關鍵權衡：chunk 大小、top-k、重排（rerank）、延遲與成本、幻覺與「檢索不到就承認」。

## 常見陷阱

- 只向量、不理權限 → 泄露其他租戶資料
- chunk 太大／太碎 → 檢索準、生成卻差（或相反）
- 不評估：沒有 golden set／人工抽樣，無法知好壞
