# Matryoshka／可變維度：截前綴，唔係另外一個模型亂切

> 2026-11-21 · AI warm-up · 工程面試向  
> 選型見 [embedding-model-selection.md](./embedding-model-selection.md)；索引與量化見 [vector-index-tradeoffs.md](./vector-index-tradeoffs.md)；換模／版本見 [embedding-refresh-drift.md](../05-mlops/embedding-refresh-drift.md)。**本篇講：MRL 點樣令「前 k 維獨立好用」、截斷後要重正規化、同 PCA／量化有何分別，以及生產上點做分維召回同版本釘死。**

## 人話

一條 3072 維嘅向量好食內存。有人會想：「可唔可以只用前 256 或 768 維？」普通 embedding **唔可以亂切**——前面幾維並冇被訓練成完整語義，切完質量會崩。

**Matryoshka Representation Learning（MRL，套娃）** 喺訓練時就對多個前綴長度一齊加損失，令「前 256／768／1536／3072 維」各自都係可用嘅表示。好似套娃：細嗰個喺大嗰個裡面，切前綴就得到短向量，唔使另外訓一隻模型。OpenAI text-embedding-3 嘅 `dimensions` 參數就係呢類能力。

後端類比：好似一張已經按重要性排好欄嘅寬表，你可以用前 N 欄做粗索引；但前提係 schema 真係噉排好。亂切一個沒有 MRL 嘅模型，等於隨便丟欄位。面試官想聽：截斷之後要做乜、query／doc 維度要對齊、同量化有何分別、可唔可以同一庫混放唔同維度。

## 面試短答

- **只對「標明支持 MRL／可變維度」嘅模型截前綴。** 非 MRL 模型前綴無保證；要降維應另訓，或用該模型官方支援嘅方法，唔好默認 `vec[:256]`。
- **一定切同一個前綴，而且截完要重新 L2 normalize。** 原向量係全維單位長，前綴嘅範數通常 < 1，直接拿去打餘弦會歪。query 同 document 必須用同一個 d。
- **唔同 d 就係唔同索引幾何，唔好混喺同一個 HNSW collection。** 256 維同 1024 維唔能當同一空間嘅點。Alias、cache key、`embed_version` 要帶 `model + dims`（以及 prefix／instruction）。你可以離線存全維、查詢時截到所需 d，但線上 ANN 索引本身要按一個 d 建。
- **同 PCA、隨機投影、量化係三條唔同軸。** PCA 係事後擬合一組基底，要存投影矩陣，亦唔係「前 k 維」。量化（int8／PQ／binary）係壓每維嘅位元，d 不變。MRL 係減 d。三者可疊加，例如 MRL-256 + int8，但要分開評估，唔好當成同一招。
- **生產常用「低維粗召回 + 同條向量高維精排」。** 例如用 256 維 HNSW 撈 200 條，再對候選用內存裡嘅 1024／全維做精確打分，然後先上 cross-encoder。精排用嘅高維來自**同一條已存向量嘅更長前綴**，唔使再 embed 一次。呢點係 MRL 相對「另外一隻細模型」嘅運維優勢。
- **只存短向量可以慳內存，但會失去無成本升級精排嘅能力。** 2M × 3072 × 4B ≈ 24GB；截到 256 維約 2GB（未計圖）。若你確定永遠只用 256，可以只物化短向量；若想保留 refine，至少對熱索引存到你會用嘅最大 refine 維度。
- **質素唔係單調「維度越大越好」，但狠截通常先傷精確標識。** 錯誤碼、合約地址、短代號 slice 往往比口語語義題更早跌。要用自己嘅 slice 畫「d vs recall／nDCG／p95／內存」曲線，揀達標嘅最細 d，唔好抄供應商標榜。
- **改 d 要當一次索引切換。** 即使模型沒換，256→768 都要新 collection、shadow、alias；query 端一齊切。唔可以「部分 doc 已用新 d、query 仲用舊 d」。

## 常見追問（連答案）

**Q1：截斷之後唔做 normalize 會點？**  
A：餘弦（或你把向量當單位長嚟用嘅內積）會偏離訓練時嘅幾何，近鄰排序會亂，而且不同文檔前綴範數唔同，等於偷偷加權。截完一定重新單位化，再入索引或打分。

**Q2：可唔可以同一個 HNSW 放 256 同 1024 兩種點，query 先短後長？**  
A：唔可以當同一空間混插。要嘛兩個索引，要嘛只建短維索引，候選再讀出更長前綴做暴力／小範圍精排。後者正是常見 adaptive retrieval。

**Q3：MRL 截短係咪可以代替 PQ／int8？**  
A：唔代替。一個減維度、一個減精度。內存緊時兩者可以一齊用，但誤差會疊加，一定要喺自己數據上看 recall 同尾延遲。二元量化尤其要配高維 refine。

**Q4：非 MRL 模型用 PCA 壓到 256，同 MRL 截前綴有咩分別？**  
A：PCA 要喺你嘅向量集上擬合，query／doc 都要乘同一矩陣，換模或數據漂移可能要重擬合；MRL 前綴係訓練時就對齊嘅，無需額外基底。效果亦唔保證一樣。唔好把 PCA 分量誤叫 Matryoshka。

**Q5：API 調 `dimensions=256` 之後，舊嘅全維庫可唔可以繼續用同一 alias？**  
A：唔可以混查。舊向量係全維（或舊 d）空間；新請求截 256 並 normalize 之後，要對 256 維索引搜。正確做法：存全維時可衍生短索引，但查詢必須打對應 d 嘅 collection；版本鍵包含 dimensions。

## 小練習

**題：** 知識庫 2M chunks，現役模型支持 MRL，全維 3072，已建 3072 維 float32 HNSW，內存吃緊。同事提出四句：（1）全部改 `vec[:256]` 原地覆寫同一個 collection，query 亦切 256，唔使 normalize，因為「只係少幾維」；（2）非 MRL 嘅舊備份模型一併用同一方法切，省得兩套邏輯；（3）有咗 256 維就可以停 int8／停 BM25；（4）精確代號 slice 跌少少無所謂，只要平均 nDCG 唔跌。你會點評，同埋會點落地？

**參考答案：**  
1. **唔可以原地混寫，亦一定要重新 normalize。** 256 同 3072 唔同幾何；應建新 256 維索引（或由全維派生），shadow 後切 alias。截完做 L2 norm。  
2. **非 MRL 唔能默認切前綴。** 舊模型維持原 d，或走官方／擬合過嘅降維，唔好共用 `[:256]`。  
3. **MRL 唔取代量化，更唔取代 BM25。** 256 維對錯誤碼／代號可能更弱，hybrid 更要留。int8 可疊加但要單獨評估。  
4. **平均 nDCG 不夠做閘。** 代號、錯誤碼、口語、中英夾雜分開報；代號 slice 跌就要加 lexical／唔好再狠切，或只對語義流量用短維。  
5. **落地：** 若要 refine，保留全維或至少 1024 維存儲，256 做一階、長前綴做候選精排，再決定要唔要 CE。`embed_version` 釘 model + dims；畫 d–質量–內存–p95 曲線後先 canary。
