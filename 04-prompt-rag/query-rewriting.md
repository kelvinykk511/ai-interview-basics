# Query 改寫：多輪指代、Multi-query、HyDE、Multi-hop

## 人話
用戶問嘅句子通常唔適合直接拎去搜：「咁佢嘅手續費呢？」冇主語；「VIP 同普通有咩分別」其實要搜兩樣嘢。Query 改寫就係喺檢索前，先將問題變成「好搜」嘅一句或幾句。

## 面試短答
1. **多輪補全（condense）**：用對話歷史把「佢」換成實體，生成獨立問題。最常見、收益最大。
2. **Multi-query / 分解**：拆成多條子查詢並行搜，結果 RRF 合併再 rerank，提升召回。
3. **HyDE**：叫 LLM 先寫一段「假答案」，用佢嘅 embedding 去搜，適合問題好短、文檔好長嘅語義落差；但假答案可能帶錯實體，事實型 / 精確 ID 查詢唔適合。
4. **Multi-hop**：第二步要靠第一步結果（「CEO 讀邊間大學」→先搵 CEO 係邊個），用迭代檢索 / agent loop，設最大跳數。
5. 代價：每次改寫多一次 LLM 呼叫（加延遲同成本）→ 用細模型、路由判斷係咪需要改寫、同 retrieval 並行。
6. 保留原 query 一齊搜（原 + 改寫做 hybrid），避免改寫改錯導致全盤皆輸。

## 常見追問（連答案）
- **Q：點知改寫有冇幫到？**  
  A：用 retrieval eval（recall@k、MRR）A/B：原 query vs 改寫，特別睇多輪樣本；同時監控延遲 P95。
- **Q：改寫將「USDT-TRC20」改成「USDT」點算？**  
  A：關鍵實體 / 代碼 / 數字要硬保留：prompt 要求原樣保留，或者抽實體後校驗改寫結果仍包含；BM25 用原 query 保底。
- **Q：Multi-query 生 5 條，延遲爆？**  
  A：並行檢索；條數按問題複雜度動態；子查詢共用 embedding batch；總結果先去重再 rerank，控制 rerank 候選數。
- **Q：改寫會唔會洩漏 / 帶錯租戶？**  
  A：改寫只改文本，tenant filter 喺檢索層由系統加，唔交俾 LLM 決定。

## 小練習
**題：** 對話：「我想問 Trust Wallet 提幣去你哋平台要幾耐？」→「咁如果揀錯網絡呢？」第二句直接搜效果差，請寫出你嘅改寫策略同改寫結果。
**參考答案：** 用 condense：結合歷史得出獨立問題「從 Trust Wallet 向本平台充值時選錯網絡（鏈）會點樣？資產能否找回？」。可再 multi-query 拆成「充值選錯網絡如何處理」「錯鏈充值找回流程及費用」，連同原句一齊 hybrid 搜，RRF 合併 + rerank。保留「Trust Wallet」「網絡」等關鍵詞；用多輪樣本做 recall@5 對比驗證收益。
