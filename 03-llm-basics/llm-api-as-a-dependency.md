# 把 LLM 當依賴服務（後端視角）

## 人話

對後端來說，LLM 很像一個**高延遲、非確定性、按 token 計費**的外部 API：你要處理超時、重試、限流、降級，還要接受同一輸入可能不同輸出。

## 面試怎麼答

- 特性：高 P99、輸出不穩、成本與 prompt/completion tokens 相關
- 工程手段：超時、冪等 key、電路熔斷、緩存（相同 prompt 哈希）、流式 SSE、隊列削峰
- 和普通 HTTP 依賴的差別：不能只靠「重試到成功」——重試會疊成本，且結果可能變

## 常見追問

流式輸出怎麼對賬／怎麼取消？→ 客戶端斷開要能取消上游；部分 token 已產生仍可能計費。
